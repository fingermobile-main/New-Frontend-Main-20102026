## 🔄 Cross-Page Link Patterns

### Mobile-Optimized to Original Pages
All mobile-optimized pages link to original `_page.html` files in burger menus for consistency with the broader platform.

### Mobile-Optimized to Mobile-Optimized
Some pages (like index_mobile.html) link to other `_mobile_optimized.html` files for a consistent mobile experience.

### Recommended Link Strategy
```
Mobile Users: index_mobile.html → _mobile_optimized.html pages
All Users: Burger menu → _page.html pages (original)
Fallback: Any broken link → index_mobile.html
```

## 🎯 Routing Best Practices

### 1. Consistent Naming
- Original pages: `*_page.html`
- Mobile-optimized: `*_mobile_optimized.html`
- Index pages: `index*.html`

### 2. Asset Paths
- All assets use relative paths: `./assets/icons/`
- Manifest at root: `./site.webmanifest`
- Favicon: `./assets/icons/favicon.ico`

### 3. Navigation
- Burger menu links to original pages
- App cards can link to mobile-optimized versions
- Desktop nav links to original pages

### 4. Fallbacks
- All pages have working headers/footers
- Burger menu always accessible
- No orphan pages (all linked from somewhere)

## 📝 Notes

### Intentional Design Choices
1. **Footer links use `href="#"`** - These are placeholders for future implementation
2. **External avatar URLs** - Using randomuser.me for demo purposes
3. **Two page versions** - Original `_page.html` and `_mobile_optimized.html` coexist for different use cases

### Known Limitations
1. **Offline avatars** - External images won't load offline
2. **Mixed link targets** - Some pages link to `_page.html`, others to `_mobile_optimized.html`
3. **No 404 page** - Missing pages show browser default 404

### Future Improvements
1. Create URL routing layer (JavaScript-based)
2. Implement 404 fallback page
3. Add link validation script
4. Create redirect map for old URLs
5. Implement deep linking support
